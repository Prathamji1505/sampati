# Report checks

Mode: Operate. Routes: `#checks` and `#demo/checks`. Narrow extension of the existing workspace tool system.

THESIS: Explain source-record findings and make the evidence easy to inspect without inferring aircraft readiness.

OWN-WORLD: Inherit Sampati's existing charcoal/crimson/ivory palette, Yatra One page title, DM Sans tables, restrained status colours, flat borders and approved artwork. Use existing buttons, sidebar, filter row and internally scrolling tables. No new raster or system token.

STORY: Open Report checks, filter reports needing attention, expand named findings, inspect the accepted source record or open the incoming inbox, then export the filtered evidence if useful. Checking and exporting never change source reports.

FIRST VIEWPORT: Existing workspace header followed by check time/revision, refresh/export actions and a concise explanation of what a data check means. A single register-like table carries source facts and findings. Forms stack and the table scrolls internally at narrow widths. Page controls remain visible outside the scrolling table.

FORM: Code-led preservation extension; seed none. Reuse the approved workspace composition and known controls for a specified data-review task, without opening a new visual concept or adding decorative motion.

QUALITY BAR: Clear separation between reported status and check result; actionable reasons/evidence; loading, error, empty and filtered states; workspace isolation; 40px standard/44px touch buttons; keyboard access; contained 1440/1024/390/320px layouts; explicit export of all filtered results rather than only the current page; unchanged register, imports and revision after checks. Preserve existing guide/footer work and design-system files.
